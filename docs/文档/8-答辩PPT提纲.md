## 第 2 页：项目目标与系统架构　【[你的名字]　约 40 秒】

- **目标**：高并发查票/购票的火车票预订系统
- **核心难点**：座位是按区间拆分的组合商品（同一座位可卖给不重叠区间的多个乘客）
- **架构图**：Gateway → user / ticket / order 三个微服务 + MySQL(分片) / Redis / RocketMQ
- **思路一句话**：位图表达区间占用 + 多级缓存扛查询 + Lua 原子操作防超卖 + MQ 异步解耦下单

## 第 3 页：核心设计 — 座位位图　【[你的名字]　约 40 秒】

- 行式位图：座位 k 在区间 s 的位置 = `(k-1)×区间数 + (s-1)`
- 示例：90 座 × 4 区间 = 360 bits = 45 bytes
- 全量位图仅 **2.2MB**（15天 × 981 车次 × 3 类型）
- 一次 AND 运算判断区间是否空闲

## 第 4 页：查票与购票性能优化　【[你的名字]　约 50 秒】

**查票**：引入 Caffeine 本地缓存，静态数据进 JVM

| | QPS | RT |
|---|---|---|
| 优化前 | 600~800 | 280ms |
| 优化后 | 11,000+ | 5~7ms |

**购票**：同步调用 → RocketMQ 异步解耦

| 阶段 | QPS | P99 |
|---|---|---|
| 同步 HTTP | ~300 | 197ms |
| RocketMQ | ~1,500 | 30ms |

关键：双锁(本地+分布式) + Lua 原子扣减，座位级锁粒度
